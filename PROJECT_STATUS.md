### What was built
- `backend/Code.gs` — Google Apps Script web app, to be pasted into the Sheet's Apps Script editor.
  - Sheet tab `Tasks`: `id, subject, category, title, status, due, note, deleted, updatedAt` (plain-text columns, one row per task, every task linked to its subject). Deletes are soft (`deleted = TRUE`).
  - Actions (POST, `text/plain` JSON, no CORS preflight): `login`, `list`, `upsert`, `delete`.
  - Access codes live in Script Properties (`CODE_english`, `CODE_math`, `CODE_hebrew`, `CODE_science`, `CODE_viewer`), generated by `setup()`, shown by `showCodes()`, replaceable with `rotateAllCodes()`. Subject code = edit own subject only; viewer code = read-only for all (for the pedagogical coordinator / principal). The server enforces this on every write.
  - Web app deployment settings to use: Execute as **Me**, Access **Anyone**.
- App changes (design unchanged apart from the items below):
  - `src/storage/sheetsApi.js` (API calls; only the access code is kept in localStorage — never task data), `src/config.js` (`API_URL`, currently placeholder `PASTE_WEB_APP_URL_HERE`, override with `VITE_API_URL`), rewritten `src/state/store.js` (optimistic updates, debounced background saving, retry, 30 s polling + refresh on tab focus, flush on page hide), `src/views/login.js` (access-code / loading / connection-error screen), `src/components/saveStatus.js`.
  - Small visible additions: access-code screen, footer "נשמר ✓ / שומר…" indicator, log-out button replacing the old reset button, empty-subject message, read-only mode for viewer / other subjects (no add button, disabled fields).
  - Checklists start empty; all tasks are deletable by their subject's coordinator.
  - Removed old demo data code (`seedTasks.js`, localStorage module). `CLAUDE.md` updated for the new architecture.
- Not connected to the Principal's Dashboard (explicitly out of scope).

### Local simulation test results (all passed)
Backend logic (`Code.gs` run unchanged against a stubbed Apps Script + in-memory sheet): codes format/uniqueness; bad/missing code rejected; login (editor, viewer, lowercase + dashed code); validation (status, category, empty title, bad date, bad id); editor writes own subject only; cross-subject write/delete/id takeover forbidden; viewer cannot write/delete; upsert updates in place (no duplicate rows); soft delete; header row; malformed JSON handled.
App in the browser against a local mock server using the same protocol: wrong code message; login; add task, status change, note → all reached the mock sheet; reload/new device loads saved data; viewer is read-only; change from another device appears; English editor sees Math read-only; delete; log out; Presentation Mode and logo; production build passes.
